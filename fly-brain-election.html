160 Hz และ 60 Hz มาจากไหน?

แผนเดโมกำหนดสูตร Hz = round(คะแนน × 200 / 20) × 20 จึงได้ 0.8 → 160 Hz และ 0.3 → 60 Hz คะแนน 0.8 และ 0.3 เป็นตัวอย่าง ส่วนเพดาน 200 Hz และช่วงปัดค่า 20 Hz เป็นค่าที่แผนเลือก ยังไม่มีการสอบเทียบคะแนนข้อความกับข้อมูลการตอบสนองต่อรสชาติจริง

Hz ในขั้นตอนนี้หมายถึงอัตราเฉลี่ยของสัญญาณกระตุ้นแบบ Poisson ที่ป้อนเข้ากลุ่มเซลล์ประสาท ไม่ใช่หน่วยวัดความหวานหรือความขม และไม่ใช่อัตรา MN9 ที่อ่านออกมาหลังจำลอง โมเดลต้นทางเปิดให้กำหนดอัตราอินพุตสองกลุ่มผ่าน r_poi และ r_poi2 โดยค่าเริ่มต้นในโค้ดคือ 150 Hz และ 0 Hz ตามลำดับ

งาน 3 — ใช้ Claude แปลงข้อความเป็นคะแนนรสชาติ

สร้าง flyvote/traits.py ตามแผนเดิม เรียก client.messages.parse หนึ่งครั้ง โดยใช้โมเดล claude-opus-5-5 โครงสร้าง Traits ของ Pydantic และ output_config={"effort": "low"} คำสั่งระบบกำหนดให้แปลงนโยบายพรรคเป็นรสชาติที่แมลงวันรับรู้ ตัวไคลเอนต์ไม่รับ API key ผ่านอาร์กิวเมนต์ แต่จะอ่านจาก ANTHROPIC_API_KEY หรือโปรไฟล์ ant auth login

ไฟล์

  • สร้าง flyvote/traits.py

การทดสอบ

  • จุดทดสอบ: ตรวจด้วยตนเองในโน้ตบุ๊ก การเรียก API จริงมีค่าใช้จ่าย และการตรวจโครงสร้างข้อมูลเป็นหน้าที่ของ Pydantic
  • เรียก score_party("ทดสอบ", "สัญญาว่าจะแจกน้ำตาลฟรีให้แมลงวันทุกตัว"); appeal ต้องมากกว่า 0.5 และ reason ต้องไม่ว่าง (AC2) ตรวจด้วยตนเอง
  • score_party("ทดสอบ", "") ต้องเกิด ValueError โดยไม่เรียก API (AC2) ตรวจด้วยตนเอง

import anthropic from pydantic import BaseModel, Field SYSTEM = """แปลงนโยบายของพรรคการเมืองไทยเป็นรสชาติที่แมลงวันผลไม้ จะรับรู้ โดย appeal = ความหวาน (0..1), aversion = ความขม (0..1) ให้คะแนนข้อความเดียวกันเหมือนเดิมทุกครั้ง reason: เหตุผลสนุก ๆ หนึ่งประโยค""" class Traits(BaseModel): appeal: float = Field(ge=0, le=1) aversion: float = Field(ge=0, le=1) reason: str def score_party(name: str, description: str) -> Traits: if not description.strip(): raise ValueError(f"{name}: กรุณากรอกคำอธิบายก่อน") ถ้าคำอธิบายว่าง Claude อาจให้คะแนนพรรคจริงจากความรู้ของตัวเอง จึงต้องใช้ข้อความของทีม หรือไม่ประเมินเลย client = anthropic.Anthropic() response = client.messages.parse( model="claude-opus-5-5", max_tokens=1024, system=SYSTEM, output_config={"effort": "low"}, messages=[{"role": "user", "content": f"พรรค: {name}\n\n{description}"}], output_format=Traits, ) return response.parsed_output ตามแผนเดิม ไม่ใช้ prefill หรือบังคับ tool_choice เพราะทั้งสองแบบส่งคืน 400 บน claude-opus-5-5 ใช้ผลลัพธ์แบบมีโครงสร้างเพื่อรับ JSON

สมมติฐานใช้ไม่ได้เมื่อ
n_run=5 รอบต่อพรรคให้สัญญาณเพียงพอสำหรับเดโม (งานวิจัยใช้ 30 รอบ)อัตรา MN9 ผันผวนมากกว่าช่องว่างคะแนนระหว่างพรรค วิธีแก้: เพิ่ม n_run ในโน้ตบุ๊ก และยอมรับเวลาจำลองที่นานขึ้น
ค่า temperature ของ softmax ที่ 10 Hz ทำให้ความน่าจะเป็นแตกต่างกันอย่างเห็นได้ชัดทุกพรรคได้ค่าประมาณ 25% หรือพรรคหนึ่งได้เกือบ 100% วิธีแก้: ปรับ temperature ในเซลล์ที่ 5
brian2 2.5.x ติดตั้งบน Python 3.11 ผ่าน wheel และคอมไพล์ด้วย Command Line Tools ที่มีในเครื่องได้ติดตั้งไม่สำเร็จ วิธีแก้: ใช้ Python 3.10 หรือตั้ง prefs.codegen.target = 'numpy' และยอมรับการรันที่ช้าลง
แผนยังไม่จัดการกรณี Claude ปฏิเสธคำขอ ทักษะที่อ้างอิงในแผนเดิมแนะนำพารามิเตอร์ fallbacks ฝั่งเซิร์ฟเวอร์ แต่แผนนี้ละไว้เพื่อใช้ parse กับไคลเอนต์ที่ไม่ใช่รุ่นเบตาคำอธิบายพรรคกระตุ้นตัวตรวจความปลอดภัยจนเซลล์เกิดข้อผิดพลาด วิธีแก้: ปรับถ้อยคำในคำอธิบาย
